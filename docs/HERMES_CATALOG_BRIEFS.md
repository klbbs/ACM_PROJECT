# Hermes 简略题库与多类别预筛

## 同步和抽题分阶段

题库同步首先批量读取公开列表或公开索引，保存题号、题名、官方链接、原生难度/分数、可验证标签、可验证日期，以及列表本身提供的简略聚合统计。同步不逐题抓取题面、源码或 AI 报告，也不为同步全库逐场下载完整榜单。

- Codeforces：`problemset.problems` 的题目和 `problemStatistics`，加 `contest.list` 的比赛日期。当前批量题库契约仍只包含已结束且具有官方 rating 的普通比赛题，不能声称已经同步全部 Gym。
- AtCoder：Kenkoooo 公开题目/比赛索引、难度模型和分数数据，辅以有界官方比赛归档及 ACL 任务列表；模型大索引在同次同步中复用，不重复下载。第三方模型、原生点数都保留原来源，不伪装成 CF 官方评分或官方标签。
- 洛谷：公开题目列表批次。继续保存分页游标，后续同步接续，而不是反复从前几页开始。
- 牛客：公开题库列表批次；标签和统计仅来自实际返回行。表头与 `colspan` 一起确定列含义，不能拿一个无表头数字猜测通过量。

抽题流程先使用已存简略元数据按登录状态、提交/推荐排重、日期、分数及多类别表达式预筛。CF 的 `evidence_only` 分支会按上述条件产生有界候选切片，再至多补查三场普通比赛及两场 Gym 的完整比赛窗口统计，用于原有综合难度策略；这不是全题库榜单同步。最终正式候选仍重新检查综合分数与条件，抽中后才读取完整题面和生成报告。

保留既有政策：有合格比赛窗口证据时，CF 综合评分使用官方 rating 45% 与比赛窗口估计 55%。无评级 Gym 缺少足够可核验比赛统计时仍不能入选。简略列表里的累计人数/提交率不替代比赛窗口统计，也不会被强行换算成 CF 分数。

## `brief_statistics` 格式与统计口径

仅在存在有效统计时保存这个小对象：

| 字段 | 含义 |
| --- | --- |
| `scope` | `all_time_users` 或 `all_time_submissions` |
| `solved_count` | 累计通过的不同用户数，仅限人数口径 |
| `submitted_count` | 累计提交次数，仅限提交口径 |
| `accepted_count` | 累计通过提交次数，仅限提交口径 |
| `acceptance_rate` | 累计通过提交数 / 累计提交数，范围 0～1；不是百分数，也不是比赛窗口通过人数占比 |
| `source` | 固定、公开的列表/API 地址 |
| `observed_at` | 采集该快照的 Unix 时间戳 |

当前来源对应如下：

- CF `solvedCount`、牛客 `acceptPerson`（表头“通过人数”）：`all_time_users`，仅有 `solved_count`，没有分母就没有通过率。
- 洛谷 `totalSubmit`、`totalAccepted`：`all_time_submissions`。有效总提交量大于零且通过数不超过总提交量时才计算比例。只有一个计数字段、零分母、无效类型、负数或矛盾计数都不能推导比例。
- AtCoder 公开难度模型/原生点数保留已有专用字段；模型不是通过量统计，不能塞入上述人数/提交量字段。

更新批次未提供统计时保留上次有证据的快照及其旧时间；提供新快照时整体替换统计对象，不能把新的分子与旧的分母拼成一个貌似实时的比例。已有 `contest_statistics`、来源、官方日期与标签合并逻辑保持独立。

## 多类别条件

API 的 `topic` 仍是字符串，例如 `dp,博弈论`，不改变旧请求的持久化载荷与幂等指纹。客户端 `/roll` 命令应把类别表达式传入这个字段。

- `dp,博弈论`、`dp，博弈论`、`dp&博弈论`：两个类别都必须满足。
- `dp|博弈论`：满足任一类别。
- `dp|games&math`：动态规划，或同时满足博弈和数学。逗号及 `&` 优先于 `|`。
- 支持至多八个类别，不接受括号、空类别或连续操作符。
- 别名先规范化、去重；细分算法不能仅凭宽泛标签认定，已批准的方法可行性证据按具体专题分别生效。

元数据预览和排除原因统计共用上述匹配逻辑，不调用 AI 或平台网络。候选的 `brief_statistics` 保持附着在对应题号上，供后续模型读取；它不是已提交、已完成或已签到的证明。

## 开发检查边界

`tests/test_catalog_briefs.py` 覆盖批量统计、无分母不造率、数值验证、列头语义、旧快照合并与 AtCoder 模型索引复用。`tests/test_hermes_brief_integration.py` 覆盖简略统计在 AND/OR 查询中的保留、预览/诊断一致和累计通过人数不改变 CF 比赛评级。

这些是合成、隔离的开发检查，不是官方平台交题或线上 AI 抽题验收。公开列表字段的人工核对也不能替代用户登录及真实提交路径验收。
