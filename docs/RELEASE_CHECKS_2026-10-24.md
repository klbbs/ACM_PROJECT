# 0.20.4 日志排查与本地检查

用户授权：检查服务器日志、修复问题、整合协作改动并发布新版本。本轮只读访问正在运行的 0.20.3 容器；没有修改服务器配置、重启容器或部署。

## 线上证据与处理

| 观察 | 结论与处理 |
| --- | --- |
| 近期结构化日志记录牛客 `platform.qr.failed`，原因 `success_data_missing`，官方码为整数 0 | 省略 `data` 的官方成功响应被误拒绝。兼容省略字段，但仍核验本次扫码会话的官方首页身份与有效会话；不会仅凭状态码绑定。 |
| AI 设置保存出现 400，测试任务提示未保存默认模型；服务器仅配置内置厂商域名 | 新增管理员后台持久化域名白名单，不要求手工改服务器环境变量；连接测试先保存表单，配置不完整时不创建任务。 |
| 历史 AI 任务有两条笼统的“超时、网络异常或 JSON 无效”信息 | 旧记录无法可靠再区分真实原因。后续请求拆分超时、网络连接、JSON 解码及响应结构错误，并将固定原因代码写入日志，不输出原始异常。 |
| 多用户请求记录为 `/{path:path}` | 父子 ASGI 共用日志上下文，记录子应用匹配到的路由模板，父层只记录一次。保留用户隔离，不记录路径实参或查询参数。 |
| 检查窗口内无 ASGI 未处理异常、运行日志写入故障或 HTTP 500 记录；有未登录请求的 401 和少量 400 | 401 表示认证拦截，不能当作后台崩溃。历史工作台 400 没有保存足够上下文，无法强行归因；新日志补充接口定位。观察仅覆盖保留的日志窗口，不代表所有功能真实可用。 |

仅提取固定错误类别、计数及协议码；没有将线上 Cookie、Key、数据库或原始响应复制到仓库。

## 功能与边界

- 扫码与手动 Cookie 导入是独立入口；扫码自动取得本次官方会话，用户不需要再导入凭据。匿名、无会话、账号不符、取消或过期均不绑定。
- 管理后台批准/撤销自定义 AI 主机名；配置与审计原子持久化，写入失败不污染内存。事务内复查当前管理员与登录会话，沿用 CSRF 和限流。内置域名由环境配置维护。
- 自定义域名的撤销同步影响已有工作空间，尚未发送的生成请求和模型目录每页请求都会重新检查；不承诺中止已经发送到外部的请求。
- 连接测试保存失败或表单在保存时又有改动时不测试旧配置，防止重复点击；没有配置模型或 Key 时直接提示。模型测试只发送固定提示，不发送训练源码。
