# 刷题工作台（0.5.0，第一阶段）

当前支持 Codeforces 公开题。服务器无需桌面；用户使用自己的浏览器完成平台提交。服务端不编译、执行用户代码。

## 使用流程

1. 在「连接与设置」添加自己的 CF handle。在「今日练习」同步题库，可再生成 AI 推荐。
2. 在「刷题工作台」选择题目，或者输入 `4-A` / 官方题目链接。后台抓取英文题面和样例，保留原题链接。数学公式以文本显示，图片需查看原题；Cloudflare 验证失败会显示错误，并保留原缓存。
3. 右侧代码编辑器支持 C++17/20、Python3、Java17 标签、Tab 缩进、Ctrl/Cmd+S 和 1.6 秒防抖保存。代码最多 **64 KiB UTF-8**。同题跨页修改会出现版本冲突；先下载本页代码再重新载入，避免覆盖。
4. 点击「保存提交快照」，下载这份代码，在官方提交页选择对应语言并提交。保存快照本身**不代表远程提交成功**。
5. 填写官方提交号并核验。只能关联当前用户已配置的账号，校验题号、个人提交和时间；提交不能早于快照 5 分钟。每次查询最多查本场比赛最近 600 条该账号提交，每份平台记录只能关联一个快照。判题中可每隔至少 20 秒手动刷新。
6. 选好 AI 通道和模型，并勾选发送数据同意项后，可以逐次请求小提示，或对未通过快照进行错因复盘。同步判题时可额外勾选自动复盘。自动复盘失败不会丢失判题，可重新发起复盘。

当前只能核验平台账号、题号和时间，**不能核验远程源码与本地快照的对应关系或语言是否一致**。复盘结论仅针对用户保存的快照，并显示该限制。未知平台状态一律按判题中处理；重判改变结论时旧复盘失效。

## AI 引导和训练数据

- 每次提示分析题面和已有提示，只输出一个短提示与一个问题，每题最多 8 次。未主动点击不会调用提示 AI。
- 错因复盘提交单次代码快照与实际判题信息，不发送账号 Cookie、API Key 或其他用户数据。AI 指出一个可疑点或行号，以问题引导自查，不请求完整解法。
- 服务端校验输出字段、长度、行号，并拦截常见代码格式。模型语义存在不确定性，不能保证所有输出都没有解题信息；不把 AI 推测当作已证实的薄弱项，也不编造隐藏测试。
- 草稿、快照、提示与复盘保存于当前用户的 SQLite 数据库；共享资料不会自动包含源码。普通能力分析和推荐只接收聚合练习次数、核验判题与 AI 错因类别，不接收源代码。
- 左侧「匹配指数」由难度接近度、近期未通过题目的关联标签和已保存的 AI 推荐计算，不是通过概率；每张卡标明规则匹配或 AI 推荐来源。
- 每用户最多 200 道草稿、2000 份快照。沿用多用户会话、CSRF、来源校验、费用操作限流和任务配额。数据目录和数据库必须纳入服务器备份，禁止上传仓库或放在静态资源目录。

## 后续阶段

- 经验证的平台代提交适配器：提交前确认代码/语言，防止网络重试导致重复提交，处理登录失效与验证码；不能将验证码失败伪装为成功。
- 其他平台题面、提交和判题适配。
- 独立隔离的编译/样例运行服务：没有安全沙箱前不在应用容器运行用户代码。
- 编辑器增强、判题自动轮询、长期训练轨迹与提示依赖趋势。

部署方式沿用 [DEPLOYMENT.md](DEPLOYMENT.md) 和 [MULTIUSER.md](MULTIUSER.md)。首次启动自动创建 `wb_*` 表，不重写历史提交或采集检查点。官方结果接口说明：[Codeforces API methods](https://codeforces.com/apiHelp/methods)。

0.6.0 起编辑器升级为 CodeMirror 6，支持本地补全与可选 Vim，详情见 [编辑器说明](EDITOR.md)。
