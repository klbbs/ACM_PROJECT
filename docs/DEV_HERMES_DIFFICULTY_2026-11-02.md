# Hermes 多维难度匹配开发记录

本次仅优化可选 Hermes 抽题模块；不部署这部分改动，不改版本号、标签或公告。原 Responses 中转524故障的定点线上修复及真实复测单独记录于 `HERMES_RELAY_524_2026-11-02.md`。

## 行为

- CF 比赛内同口径参赛人数、提交人数、通过人数与出题日期参与筛选和证据解释。用户最早日期仍是硬条件；题龄不会把累计AC人数变成难度证据。
- 至少100个样本且来源/题号/日期/单位/完整性可靠时，经验55%与官方45%结合，严格按综合分匹配；原官方分保留展示。没有官方分的Gym以经验数据初估，未知则不抽。映射是未经共同选手校准的启发式，公开比赛样本不能证明跨比赛难度等价。
- 每轮核对至多三场普通赛和两场Gym，不遍历全库。发现池预留40道官方区间内题和20道区间外题，避免优先排序后截断完全隐藏其他官方难度；比赛采样优先两场区间内，并在可用时保留一场区间外。
- 统计成功后，仅让该比赛或已有有效经验统计的CF题进入最终候选；过滤发生于60题截断之前。统计失败的比赛不能混入成功集合。有限采样没有符合题则付费AI前停止，不回退到被综合分排除的题。
- Gym优先分+0.12通过系统随机权重实际提高概率，不改变难度、不计完成分。仍排除已尝试/跳过/交付/客户端排除/对战占用题，保留最终身份与题面重校验。
- Gym使用本人已验证绑定的现有API密钥。现场统计仅在比赛名称、日期、完整题号对应后从XCPCIO/ICCPC补齐；不采用模糊映射。缓存仅存公共题目元数据和聚合值，不存队伍/成员、签名URL或私密凭据。
- 新增`checking_difficulty`进度及结果中的`contest_evidence_sync`。候选预览仍是只读，不发送统计采集或AI请求。提示词与能力目录同步说明证据和限制。

## 定向开发检查

本次变更及直接受影响范围共334项测试通过；覆盖SSE/模型schema、统计解析、评分、真实解析器形状到评分、Gym/现场源、候选发现与截断、加权随机、历史排除、取消/账号变更、CSRF/多用户隔离及安全日志。仅有既有TestClient弃用提示。Python编译、差异格式检查通过，未运行全项目检查。

协作只读复查发现并修复了计数单位不兼容、账号切换后发布、名义难度预过滤、候选截断和成功/失败统计混用等集成问题。测试中的榜单与模型返回为合成响应，不能描述为真实OJ抽题或交题成功。

采集代理对CF普通赛、XCPCIO与ICCPC各一场进行真实公开只读采集，均获取到可解析聚合；这只说明采集路径，不代表所有比赛覆盖。新的多维策略尚待真实带账号Gym及完整roll用户路径验收；未额外触发付费AI抽题。接口算法和覆盖限制见`HERMES_API.md`。
