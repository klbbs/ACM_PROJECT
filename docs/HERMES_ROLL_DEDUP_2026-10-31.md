# Hermes 连续抽题重复修复记录

本次仅本地开发。按用户授权只读查看了本地 Hermes 练习调用记录，确认存在两条不同任务返回同题；没有修改 Hermes 私人数据库、连接配置、会话或凭据。实际题号、请求标识和个人练习结果不复制进仓库。

## 原路径与原因

原流程 `Hermes.run → sync_history → pool → AI 初选` 只排除本地练习与官方提交。发给 Hermes 后放弃、未提交的题没有进入排除集合。候选虽然由系统打乱，最终题号仍由 AI 决定，不能将打乱候选称为严格的随机抽题。

## 修复

- 新增私人 `hermes_drawn_problems` 表，从已有成功 Hermes 任务回填。题号交付记忆与 `web_jobs` 完成结果在同一事务内更新，规范化题号唯一；同题不同任务不能同时成功。失败/取消不消费题号，同键重放仍恢复原结果。
- 在候选采样前排除已交付题、提交/练习历史与客户端 `exclude_ids`。候选耗尽时明确失败，不自动再付费。文字、图片、新进程及历史旧任务共用这套记忆；不计 AC、签到或榜单。
- 通过系统随机源抽取一道候选，模型只接收该单题并被 schema 约束；返回 `selection_strategy=system_random_without_replacement`。这是最多60道平台均衡随机候选内的随机抽取，不宣称全平台全库等概率。
- 新增 `GET /api/hermes/problem-memory`，只输出当前工作区的规范题号和状态标志，使用稳定快照分页。SDK 可原子保存私密本地缓存，换用户工作区不能混用，并将额外排除清单在抽题前提交。
- 新增 `ensure_catalog`：本人已验证平台含 CF 时首次或六小时后匿名读取官方 `problemset.problems` 与 `contest.list(gym=false)`，复用官方解析，验证后原子发布。HTTP失败、截断、日期缺失等均保留缓存并在 AI 前停止；取消后阻止新请求和迟到发布。
- 按前序用户授权更新为 0.21.8 并增加公告，不部署服务器，不制作发布包。
