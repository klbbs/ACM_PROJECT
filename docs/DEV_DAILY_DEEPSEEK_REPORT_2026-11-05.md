# 每日题单 DeepSeek 阅读截断修复

## 原问题定位

服务器2026-11-05 16:18的同一请求日志依次出现 `ai.failed:ai_output_truncated`、`selection_reports.failed`（请求4题、已完成3份阅读）和 `daily.failed:daily_output_truncated`。失败发生在每日题单的第四份逐题阅读报告：DeepSeek Chat、`deepseek-v4-pro`、思考与强度均auto、最大输出8192；实际输出8192、其中思考8192、结束原因为length，未产生可保存的最终报告。不是候选数量错误，也不是平台访问失败。

调用链：每日生成 → Daily选题 → SelectionReports逐题完整题面阅读 → AIProvider.complete(`selection_read_report`) → DeepSeek Chat。

## 修改及边界

- 仅对DeepSeek Chat的`deepseek-v4-pro`和`deepseek-flash`，在阅读报告任务且两个思考参数均auto时，单次请求明确关闭隐藏思考，让原预算用于最终JSON。依据为当天核对的[官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)。仍传完整官方题面并严格校验题号、报告结构及适用性。
- 用户明确选择思考模式或推理强度时尊重原设置；其他模型、提供方、协议及任务不变。不修改保存配置/配置指纹，不更换模型，不增加预算，不自动重试收费请求。
- 日志记录实际策略与思考模式的固定枚举；报告来源保留已识别的自动策略，未知字段/策略不保存。不能将隐藏思考作为题解输出。
- 保持四题报告及每日题单的原子提交，失败保留旧数据，不计完成或签到。

## 开发检查

多代理分别负责原始调用链定位、参数实现、每日四题回归及独立复核。相关六个测试文件共184项通过，Python编译和差异格式检查通过，仅有既有TestClient弃用提醒。四题回归使用真实Daily/阅读服务/AIProvider，仅替换外部HTTP与官方题面边界；能复现前三份完成、第四份耗尽8192思考预算的失败，并验证修复后的四题保存及显式思考时的旧计划保留。此为合成模型响应，不代表真实OJ或真实模型四题验收。

保持应用版本0.21.9；推送主分支后按服务器管理授权备份、确认无运行任务再更新。服务器实际模型复测结果单独报告，不在仓库保存成员题单、源码、凭据或模型正文。
