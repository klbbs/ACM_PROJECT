# 平台绑定、登录检测与官方提交

本站登录与算法平台登录是两套独立会话。设置 handle / UID 是选择采集目标，不证明账号归属。服务器不需要安装桌面或 Firefox。

## 四个步骤

1. **同步信息**：在「连接与设置」选择平台，填写本人 handle / UID，保存后同步提交与资料。公开采集成功不等于已登录。
2. **登录检测**：按下面说明保存 Cookie，再点击该账号的检测按钮。核对检测返回的真实登录账号与配置标识一致。结果为无法确认或仅支持公开数据时，不应当作已验证会话。
3. **官方交题**：在实际打开官方提交页的浏览器中登录对应平台，确认账号与语言、题号，粘贴代码并亲自提交。当前是官方页面手动提交，不会自动代交。
4. **提交结果关联**：按工作台列出的支持能力填写官方提交号并核验判题。实时判题关联支持范围以界面为准；不支持的平台需先到官方查看结果，再同步账号更新训练记录。自测成功、手工完成声明、AI 分析均不等于官方 AC。

## 优先使用油猴助手

在连接与设置中复制 ACM Lab 脚本源码，在 Tampermonkey 新建脚本并保存，刷新算法平台后主动获取 Cookie。无需临时加载未签名 Firefox 扩展。脚本没有返回 HttpOnly 时，可明确选择复制当前可读部分，随后以本站登录检测为准；这不保证凭据完整。需要完整 Cookie 或检测失败时，使用下面的 F12 流程；不能把 `document.cookie` 当作完整凭据。具体安装与限制见 [油猴助手](BROWSER_EXTENSION.md)。

## Codeforces：先核对当前会话

可以选择官方Firefox Beta来获取HttpOnly，具体安装/权限步骤见 [油猴助手](BROWSER_EXTENSION.md)。先在同一浏览器普通窗口正常登录CF并打开设置页，再获取完整Cookie、保存与检测。不要同时运行稳定版和Beta中的两份助手。

服务器检测会提示是否发现CF常见会话字段`JSESSIONID`，只用于检查导出完整性；出现该字段或HttpOnly不等于登录成功，缺失时也不直接覆盖官方返回的真实身份结论。最终标准是CF设置页返回的当前身份与配置handle匹配。现有本地Cookie如果仍返回登录跳转，需要更新当前会话，不能以旧数据或合成页面宣称已验证。

## Codeforces：完整的 F12 操作

1. 在本人浏览器打开 [Codeforces 登录页](https://codeforces.com/enter)，正常完成登录和平台验证。右上角应出现本人 handle，再进入个人主页或 My submissions。
2. 按 F12，选择「网络 / Network」。Firefox 可使用 Ctrl+Shift+E；Chrome / Edge 可使用 Ctrl+Shift+I 后选择 Network。保持工具打开，刷新平台页面。
3. 在请求列表选择发往 `codeforces.com` 的 Document 或个人资料 Fetch/XHR 请求。不要选图片、广告、第三方统计或其他域名。
4. 打开「标头 / Headers」→「请求标头 / Request Headers」→ `Cookie`，复制右侧**完整的值**。折叠时展开或查看原始标头。不要复制响应标头中的 `Set-Cookie`。
5. 返回本站「连接与设置」，为 Codeforces 填写相同 handle，把完整值粘贴进 Cookie 输入框，保存配置。
6. 点击对应账号的「检测登录状态」。只有检测明确识别出真实账号且匹配配置 handle，才表示服务器此次验证了会话。未确认身份时不能认定登录成功。

格式示意，不能直接使用：

```text
JSESSIONID=你的值; RCPC=你的值; other_cookie=其他值
```

JSESSIONID、RCPC 与其他验证 Cookie 是否存在，以浏览器当前实际请求为准。复制完整 Cookie 值，不应只挑固定名称或按示例补造字段。平台验证会变化，固定 Cookie 组合不保证可用。

不要带 `Cookie:` 前缀，不要复制 `Set-Cookie`、`Path`、`Domain`、`Expires` 属性；不上传整个 HAR、Copy as cURL、整段请求头、平台密码、验证码或浏览器用户目录。Cookie 等同登录凭据，只填写到本人信任的 HTTPS 部署，不分享给成员、Git 或 AI。已保存的 Cookie 不回显；留空保留原值，清除选项才删除原值。更新后先保存再检测。

### 找不到 Cookie 或复制后无效

开发者工具要开在**算法平台**页面，而非 ACM Lab 页面。Firefox 在「标头」展开「请求标头」，必要时启用 Raw；Chrome / Edge 在 Headers 展开 Request Headers。选择登录后刷新产生的该平台页面请求，不从「Application / 存储」复制整张表，不复制其他域 Cookie。只需该平台请求 Cookie 的完整值，不需要密码、验证码、CSRF token 或全部浏览器会话。

修改输入但不保存，检测仍使用原先的凭据。检测通过只说明此次服务器识别到匹配身份，不能保证此后不过期，也不代表可自动代提交。

## 排查

- **Cookie 过期、退出登录**：重新在官方登录，复制当前请求 Cookie，保存再检测。服务器不能自动更新个人浏览器 Cookie。
- **验证码、浏览器挑战或 403/418 访问限制**：点击检测卡片的官方处理入口，在本人浏览器完成正常验证，重新获取并保存完整 Cookie，点「已处理，重新检测」。没有验证码证据的 418 会明确显示访问限制，不误判为 Cookie 过期；浏览器正常也不保证服务器 IP 可用。仍受限时使用官方页面。
- **429 限流**：按卡片提示等待后再检测；主动重检不会绕过本地防刷或官方等待。
- **网络或平台暂时不可用**：按检测原因区分超时、连接失败和平台 5xx，稍后重试；服务器网络故障不要求用户反复更换 Cookie。
- **真实账号与配置不一致**：核对 handle / UID。切换官方账号后重新复制 Cookie，或修正本站目标账号；修改昵称不能解决会话错配。
- **只有公开数据、HTTP 200、公开主页可读**：这些都不是登录证据。可以继续公开采集，但应显示未验证或无法确认。
- **服务器检测通过但官方提交页未登录**：服务器与浏览器会话不共享。Firefox 登录不会自动转移到内置浏览器；在实际打开提交页的浏览器中单独登录。
- **题面仍失败**：先检查原题访问权限、网络和验证情况。可从官方页面 F12 元素面板复制题面节点 Outer HTML 导入；Codeforces 为 `.problem-statement`，AtCoder 为 `#task-statement`。不复制整页和登录表单。手动导入不能独立验证题号，不能作为官方共享翻译来源。

## 历史提交与题面、源码

「提交记录」的「回到工作台」打开对应题目与当前草稿，并非恢复平台历史源码。公开记录通常只有题号、账号、时间、语言和判题结果；源码权限由官方控制。需要旧代码请在官方记录查看并自行复制。工作台不再要求先创建代码快照才能关联官方提交。AI 错因分析若使用当前代码，需本人明确同意，并确认与官方所交代码一致；仅凭提交号不能证明两份代码一致。
