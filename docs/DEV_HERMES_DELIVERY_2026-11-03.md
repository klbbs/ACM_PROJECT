# Hermes 结果回执开发记录

- 新增持久结果交付表：与任务完成、排重记录同事务提交；冲突整体回滚，不把没有完成的结果变成可收件消息。
- 固定消息编号和原JSON字节摘要，保留发送次数、下次发送时间与幂等ACK。结果生成、发送、收到确认分别处理。
- 用户要求的等待间隔为5秒，未确认则重发同一结果，单连接最多发送3次且有20秒总预算；未确认数据仍持久保留，重连继续。不重新抽题、调用AI或重做图片。
- 新增本人交付状态、NDJSON流与ACK接口，沿用认证、CSRF、Origin和一般限流；每进程工作区至多两个流、同任务一个流。断线/完成均释放连接，重复清理不会释放新连接的名额。
- SDK校验任务/消息/摘要，保存回调精确返回True后才ACK；ACK响应丢失只恢复同一消息。新增协议文档与AGENTS入口供其他agent阅读，明确至少一次及持久去重、图片过期、最终渠道确认边界。
- 本次直接受影响的96项定向测试通过，包括未确认重发、确认后停止、幂等/错误回执、跨用户/CSRF、并发发送租约、恢复、事务回滚和SDK保存失败。只有既有TestClient弃用提醒；没有运行全项目检查。
- 其中本地回环HTTP测试实际运行ASGI服务，逐行收到消息后通过另一个请求ACK，并验证原流结束；同时验证SDK不会等HTTP响应全部结束才收件。这是实际本地HTTP传输，使用合成结果，不是外部OJ或付费模型验收。
- Python编译及差异格式检查通过。应用版本保持0.21.9，不标注新版本、标签或公告；根据用户新授权，推送后部署至指定服务器，部署验证与上述开发检查区分。
