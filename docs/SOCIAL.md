# 排行榜、好友与对战

本功能用于已开启多人用户模式的站点。单用户模式不提供其他用户数据。通过侧栏“排行榜与好友”进入。

## 第一次使用

1. 在“连接与设置”通过扫码或 Cookie 绑定平台账号，点击“检测登录状态”。仅在确认真实登录身份后，平台身份才会自动关联榜单与对战。
2. 无需再次手工认领；每个平台账号只能属于一个站内用户，不能通过填写他人公开用户名冒领。修改 Cookie 或账号后，需要重新检测。主动解除认领后不会自动恢复，可在“我的主页 → 用于榜单与对战的平台身份”重新认领；已有其他用户持有该身份时需核实冲突。
3. 按需填写昵称和简介，并选择公开主页、加入每日榜单。两项均默认关闭。加入榜单也会公开该日的题目详情；好友能查看彼此主页。用户名及昵称可供站内检索，源码、Cookie、草稿、AI 对话不会公开。

身份认领证明此前的归属验证，不代表 Cookie 永久有效。实际登录状态仍需通过设置页检测。平台访问限制或无法确认身份时，不能用 HTTP 200 或公开资料充当成功登录。

## 每日做题榜

按北京时间 `Asia/Shanghai` 的自然日统计已同步官方 AC，按“平台 + 题号”去重。同题当天重复 AC 只计一题。仅统计已验证关联且凭据未发生变化的身份。用户可点击每行“查看当日题目”或榜单昵称，查看题目、官方链接、原平台难度/得分及标签；平台未提供的数据明确标为未标定，不把洛谷或 AtCoder 的数值冒充 CF 分数。

“同步平台题库”在更新公开题目资料后，也会独立采集已配置账号在北京时间今日的官方提交，显示完成、部分失败、失败或未配置账号的说明。提交采集失败不丢失题库结果；也可以单独点击“同步我的提交记录”重试。采集历史 AC 不会让它按今天计数，榜单仍按官方提交时间归日。

统计范围包含自主练习、每日任务和对战，和每日任务目标、K 签及题单归属无关。按官方提交时间归入对应日期，不按同步时间计数；不计未来时间的记录、草稿或代码自测。兼容旧工作台中已保存的官方 AC 证据，若同一提交已有采集记录（包括重判），以采集记录为准，避免重复统计或把旧 AC 计回。

排行榜提供“同步我的提交记录”入口，沿用账号采集任务，任务完成后自动刷新榜单。“同步题库”只下载题目资料，不下载个人做题记录；也可到工作台“同步本题提交”更新一道题的官方结果。尚未配置账号、未完成身份认领或未开启公开榜单时，页面说明相应条件。

默认展示今天，可查看最近一年的日期。对战通过的题目计入每日做题数量及普通签到；榜单显示的是当前同步进度，关闭公开榜单后会立即移出。

## 用户与好友

支持按用户名或昵称搜索。好友申请必须由接收方明确接受，发送方可撤回，接收方可拒绝。双方可解除已确认关系。未公开主页的用户只能由本人或好友查看；加入公开榜单会公开榜单题目详情。停用用户不会出现在检索和榜单中。

## CF 好友对战

- 双方各认领一个经过验证的 CF 身份，并先互相成为好友。
- 发起方选择 CF 精确难度（800～3500，100 的整数倍）和 5～180 分钟时长，默认 60 分钟。对方接受所示难度和时长后，才会抽题、开始计时。邀请 24 小时后过期。
- 接受时读取 CF 官方题库、双方完整官方提交历史；随机池只含该精确难度、双方从未尝试、未作为任一方每日任务的题目。服务器只接收官方题目数据，不能由客户端指定答案、题目或判题。
- CF API 超时、验证页、截断历史、题库错误都会阻止开始或结算。完整历史核验上限为 50000 条，超过上限时明确失败，不把截断记录当作“从未做过”。
- 每人同时仅能持有一场自己发出的待处理邀请或进行中的对战。收到的其他邀请可以拒绝；在接受另一场前先撤回自己发出的邀请。
- 通过工作台打开题面和编辑代码，目前仍使用官方页面提交，也可直接在 CF 提交。点击“核验双方官方提交”读取双方官方记录，至少间隔 20 秒；页面每 15 秒只刷新站内状态，不会自动轮询外部 API。
- 仅官方记录中与本场 CF 身份、题目及对战时间吻合的独立提交可以获胜。旧 AC、其他账号、团队提交、虚拟参赛记录及客户端自报结果不计。按首次 AC 的官方提交秒数比较；同秒 AC 平局，到时双方未通过也视为未分胜负。
- 首次 AC 或截止后至少保留 30 秒确认期；如果更早的提交仍在判题，会继续等待。核验失败保留原状态，不猜测胜者。
- 对战题会写入双方隔离库的 `battle_problem_ids`，供推荐和每日任务统一排除。官方 AC 会保存到各自提交历史，因此计入普通签到和每日榜单，但不会抵扣每日任务，不产生 K 签。
- 服务重启保留进行中对战，之后可继续核验；重启期间被中断的开始操作会取消并释放占用。参与者停用时，可由另一方刷新核验取消这场对战。

## 开发接口

所有 `/api/social/*` 接口继承多人模式的会话认证、写请求 CSRF/来源校验及限流。身份根据当前会话决定；不接受客户端 `owner_id`、胜者、完成时间或 AC 断言。

| 接口 | 用途 |
| --- | --- |
| `GET/PUT /api/social/me` | 本人主页偏好；GET 同时返回绑定账号和有效社交身份，不返回凭据 |
| `POST /api/social/accounts` | 使用近期成功登录检测认领 `{platform,handle}` |
| `DELETE /api/social/accounts/{platform}/{handle}` | 解除本人认领，当前有对战占用时拒绝 |
| `GET /api/social/users?q=...` | 用户检索，仅返回用户 ID、名称和好友状态 |
| `GET /api/social/users/{id}?day=YYYY-MM-DD` | 按主页可见性返回资料和当日题目元信息 |
| `GET /api/social/leaderboard?day=YYYY-MM-DD` | 启用公开榜单用户的去重官方 AC 排名，同分并列 |
| `GET/POST /api/social/friends` | 好友/申请列表、发出申请 `{user_id}` |
| `POST /api/social/friends/{id}` | `{action:accept|decline|cancel}`；cancel 也用于解除好友 |
| `GET/POST /api/social/duels` | 本人对战列表；发起 `{user_id,difficulty,duration_minutes}` |
| `POST /api/social/duels/{id}/action` | `{action:accept|decline|cancel}`；仅待处理邀请能取消/拒绝 |
| `POST /api/social/duels/{id}/check` | 用固定官方接口核验结果，不接受客户端判题证据 |

中央身份库新增 `social_profiles/social_accounts/social_friends/social_duels/social_duel_locks`，只保存必要社交元数据及身份凭据指纹，Cookie 与源代码仍留在用户隔离工作区。`battle_problem_ids` 是规范化题号字符串数组；每日任务生成、roll、完成、用时、K 签与推荐都排除此集合，普通签到保留对战的官方 AC。
