# Hermes 抽题中转超时定向修复

## 定位

本轮经用户授权，仅排查当前线上抽题故障。只读对照本地 Hermes 原抽题记录与服务器对应任务，确认失败发生于完整解题报告阶段：元信息步骤成功，报告请求约126～127秒后被中转站以HTTP524拒绝。同一链路也存在较快报告成功的记录，因此不是题库为空、重复题排除或登录身份失效。

原实现对 Responses 使用非流式POST，等待完整响应后再读JSON。该路径在长时间生成时容易碰到中间网关等待上限；只增大本站超时不能扩大中转站的限制。仓库不保存实际用户、题号、任务标识、本地私人记录、模型正文或凭据。

## 改动

- 仅为 Hermes 的元信息理由与完整报告 Responses 请求启用 `stream=true`，其他通道与任务维持既有传输方式，不改用户模型、输出预算和思考设置。
- 使用有界SSE读取，严格要求 `response.completed` 和完整最终response；不使用思考、delta或孤立的DONE作为报告，不从不完整片段拼出成功结果。保留原有完整JSON及业务schema验证。
- 兼容中转站忽略流式参数但返回完整application/json，不重新发送第二次请求。断流、失败、截断、过大响应及缺少最终确认均明确失败，不自动重复收费。
- 流式读取保留用户配置的空闲I/O超时，另有540秒流式硬上限及父抽题600秒总预算，避免将合法慢流提前按非流式等待时间截断；取消/超时关闭本地连接，不能保证上游撤销计算或费用。
- 日志只增加布尔 `ai_streaming` 和固定失败原因，不保存事件正文、思考、题面、源码、密钥或原始异常。524明确描述为中转网关等待超时。

规范依据：[OpenAI Responses流式事件](https://developers.openai.com/api/reference/resources/responses/streaming-events)。流式接收不能保证所有中转站都正确转发心跳或免除其上游服务故障。

## 定向检查

- SSE解析、Hermes真实AI调用方法的合成协议测试、现有API适配/schema/任务边界：95项通过。
- 直接受影响的Hermes任务与运行日志回归：71项通过。
- Python编译及差异格式检查通过。测试中的模型响应为合成数据，不代表真实付费调用成功。
- 服务器原容器为只读文件系统，直接写入被拒绝，未解除该限制。保留旧镜像和源码备份，使用仅包含三个处理模块的修补镜像，原配置、版本号、数据库及其他服务不变；更新前确认没有生成或交题发送任务。

真实复测：第一次修补错误地将用户的180秒空闲超时同时作为流式总上限，实际请求因此提前结束；已修正计时并补回归测试。最终通过现有登录会话调用原 `/api/hermes/draw/image`，请求相同1800分区间与原配置模型：任务完成，完整题目说明和报告存在，图片下载返回有效PNG。对应报告真实上游200、流式接收、耗时约125秒；服务保持运行且只读文件系统开启。这是一次原故障路径的真实复测，不代表所有题目、平台或中转站永不失败。
