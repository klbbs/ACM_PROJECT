# 更新工具专项验收（追加跨镜像版本检查中）

日期：2026-10-23。范围仅限一键更新工具；不代表其他业务功能验收，不标注新版本，不发布，不部署。

## 独立验收方法

新增 `tests/test_update_acceptance.py`。每个用例在 pytest 临时目录新建真实 bare Git remote、开发副本和旧版安装副本，产生真实提交。所有账号配置、数据均为测试数据。健康检查使用真实本地 HTTP 服务，校验公开来源 Host 头。

系统服务识别、候选运行环境构建及 systemd 启停用显式 stub；Docker 镜像构建、标签、服务启停同样用内存状态 stub。实际 Git、归档、代码切换、SQLite/WAL 快照、文件恢复和 HTTP 探测不替换。没有操作真实用户服务、Docker daemon、线上服务器及用户项目目录中的更新流程。

运行命令：

```bash
env -u PYTHONPATH .venv/bin/python -m pytest tests/test_update_acceptance.py -q
```

移除 `PYTHONPATH` 是避免执行主机 ROS 插件污染 pytest；不更改项目依赖。

## 检查项目

- 远程预检不 fetch、不加锁、不创建状态目录，并比较文件内容、修改时间与权限。
- 排斥第二个更新锁；拒绝已跟踪文件的工作区修改与暂存修改；拒绝非快进更新。
- 拒绝目标提交新增私人路径、符号链接，拒绝覆盖本地未跟踪资料。
- 候选构建失败时不停止旧服务。
- 真实 Git 快进、索引与工作区一致，用户配置及未跟踪资料保留。
- 新版健康失败时恢复旧提交、旧运行环境、含已提交 WAL 的 SQLite 与配置，保留失败数据。
- Docker 标签回滚状态及旧镜像健康检查，区分完整与不完整回滚。
- 停服请求已发送但状态确认失败时恢复旧服务。
- 健康 HTTP 响应不能覆盖目标运行实例已死亡的事实；拒绝未变化的原生服务 PID。
- 原生单元使用外部运行环境时拒绝操作；候选构建期间的用户编辑保留并中止更新。
- 目标 Compose 版本可更改 image tag 与 build target；默认相对数据/配置 bind 仍解析到实际项目根，切换与回滚分别使用新旧 tag。

## 初轮发现与修复回归

1. 备份目录先创建并写入源码归档，而备份函数拒绝任何已存在目录，导致构建成功后也无法更新。
2. `git status` 会刷新 `.git/index` 修改时间，违背无写入预检承诺。
3. Docker 回滚分支未探测旧版 HTTP 健康即可宣布回滚完成。
4. 停服函数在停止命令已执行但确认失败时，调用方不尝试重启旧版。
5. HTTP 响应成功时跳过目标服务存活检查，其他旧监听器可能导致假阳性。
6. 原生服务只匹配工作目录，未确认其实际使用项目 `.venv`，可能替换了未被服务使用的运行环境。
7. 候选构建期间新增的用户源码编辑未被复核，随后切换代码会覆盖这些编辑。

最终复测：`21 passed`。以上 7 类缺陷以及后续跨版本 image tag/build target 和真实 bind mount 回归均通过。

原 19 项通过结论已暂缓：追加检查发现 Docker 跨版本 image tag/build target 变更的升级路径未覆盖，当前等待修复和独立回归。不得据此前结果宣布更新功能完整通过。

## 验收边界

此轮不证明真实 Docker 引擎、Compose 各版本或 systemd 单元可在目标生产主机完成更新。网络依赖下载、真实前端/虚拟环境构建、发行版权限、TLS 反向代理及真实生产数据库规模未经过目标环境验收。用户授权只验收更新功能，因此未运行全项目业务验收或浏览器业务 E2E。
