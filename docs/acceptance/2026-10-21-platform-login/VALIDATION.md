# 四平台登录与 Cookie 验收（2026-10-21）

本轮仅开发和隔离验收，没有部署、连接用户服务器或代提交代码。产品不集成验证码自动识别服务；测试中处理验证码均取得当次操作确认。用户此前授权读取本人平台会话及测试登录；凭据没有进入仓库、日志、截图或 AI。

牛客公开评级/提交接口也能匿名返回相同数量，因此它们只证明数据解析可用；登录身份由固定官方首页的当前会话字段独立核验，绝不以公开资料充当已登录。

另对本地 account.toml 的旧牛客凭据做 HTTP 检测，返回200但当前身份为 expired / not_logged_in。这与上表从本人当前已登录浏览器导出的新会话不是同一份凭据；旧配置没有被覆盖。HTTP200和 Cookie 格式通过都不等于已登录。

本机开发目录与桌面目录的四平台已保存配置均做只读语法检查，全部为 valid（格式通过）；没有因此认定旧 Cookie 仍有效，也未覆盖这些个人配置。编辑框保持脱敏，服务端只回传是否保存、语法结果及数量；留空保留、填写替换、明确勾选清除。

## 本轮边界

四平台实现均有自动化流程/身份检查覆盖，不等于四平台新登录都已通过。CF仍需完成官方验证，牛客仍需一轮新的微信扫码确认；AtCoder须等待本次验证明确通过后再提交，不将勾选瞬间当作通过。洛谷官方密码登录与既有Firefox会话绑定分别通过，同一次新密码登录到绑定的连续流程仍未验收。额外将本地旧洛谷 Cookie 放入全新隔离 Chromium，调用产品 confirm 后返回 human_required / identity_unconfirmed，保存账号数为0；该旧配置与Firefox现有有效会话不同，未被覆盖。图形验证码由本人输入，或仅在取得该次操作确认后处理；过期后不沿用确认。

0.18.1补测时，CF与AtCoder的匿名官方登录表单仍返回浏览器验证要求（按产品解析器识别），没有发送密码或尝试自动处理验证。当前控制浏览器连接仍不可用。

HTTP采集头统一为桌面浏览器常见 User-Agent、Accept 和语言；这是内容协商，不是浏览器TLS指纹，也不宣称能够绕过平台验证。官方登录窗口使用实际 Chromium 网络栈、沙箱、独立上下文及受控输入。代码交题仍由用户在官方页面完成，已登录与具备自动代交能力分别展示。

可选浏览器镜像和 Compose 文件已编写；本机没有 Docker CLI，未进行容器构建或部署，不能将源码检查写成镜像运行验收。维护者可按 PASSWORD_LOGIN.md 使用官方沙箱profile自行构建。

GitHub 最终验收：[f4d5bc6 流水线](https://github.com/klbbs/ACM_PROJECT/actions/runs/39524027742)的 validate、runtime、server-codex、server-browser、server-browser-codex 全部成功。浏览器目标已实际构建并运行，chrome://sandbox 的 PID namespace、Network namespace、Seccomp-BPF 均通过。此前两轮暴露只读主目录 / Crashpad 和旧 seccomp 示例不适配现代运行库，已分别分配私有临时 XDG 目录、采用 Moby 当前默认策略加命名空间与 chroot 规则，保留默认拒绝及非特权沙箱；没有部署服务器。
