# v0.19.1：提交早于代码保存的关联修复

## 复现与原因

在官方平台提交后，再将该次源码粘贴到工作台，或在回来关联前重新保存。官方提交与本地保存相差超过五分钟时，0.19.0 会报「此提交早于代码记录」，即使本人已明确确认源码对应关系。

前一版将关联时间改为近期草稿保存时间，只处理了先保存、后提交、稍后返回的情况。保存时间仍无法证明官方提交的源码，不能拿它限制本人声明的关联。

## 修复与边界

- 主关联接口仍要求 `code_matches_submission=true`、已保存的正确 revision、本人已配置平台账号和非空源码。服务器在同一事务中记录该不可变代码 hash 的本人声明。
- 对已声明代码，允许关联早于本地保存的真实记录；四个平台共用有效时间校验，错账号、错题、非法/未来时间仍拒绝。已经关联的提交不能被另一份代码覆盖。
- 仅刷新旧内部代码记录不自动增加声明；需通过主表单明确确认。新的声明表在旧库初始化时建立，不会批量替旧记录声明源码。排队或首次核验失败删除 attempt 时，触发器同步删除声明。
- 所有源码仍为未自动核验，声明不能证明与平台远程源码相同。官方提交日期保持原样，历史 AC 不签到今日，也不显示需要重新同步签到的错误提示。

## 验证

- Python 全套 634 项通过，仅现有 Starlette/httpx 弃用警告。
- 工作台与签到专项 85 项通过，独立 agent 另行重跑 85 项通过；覆盖先提交后粘贴、稍后重存、旧声明持久化、四平台关联、拒绝错账号/题号/未来时间、失败声明清理及历史 AC 不计今日。
- 196 项前端组件/脚本通过，TypeScript/Vite 构建通过。
- 5 项浏览器回归通过：新用例采用早于当前保存一小时的合成官方提交，并阻塞自动保存请求，确认等待保存后可关联且只发起一次；同时复查 WA 复盘、AC 回看、自动提示及备注导航保护。
- 独立探针确认新表重新初始化不替旧记录生成声明，删除、队列拒绝、错账号核验失败均清理声明。
