# Gym 虚拟参赛榜单补丁：开发检查

本轮处理当天做题榜漏计反馈；不标注新版本、不制作发布包、不部署服务器。产品版本保持 0.21.1，变更记录放入 Unreleased。全部修改位于主分支，按既有约定只推送 main。

## 排查与行为

前序只读请求中，用户提供的记录属于 CF Gym/Mashup：普通 user.status 查询没有返回该提交，指定比赛的 contest.status 返回 HTTP 400 / “比赛不存在”；官方提交网页遭遇安全验证。这个现象不能证明用户没有 AC，也不意味着所有虚拟参赛都被排行榜过滤。源码中 VIRTUAL 排除只用于好友对战判胜，排行榜自身没有该过滤。本轮保留对战判胜规则。

另发现排行榜原先直接创建采集任务，未通过应用的任务启动器记录 queued 状态。首次轮询已经看到 completed 的快速任务可能无法触发榜单修订刷新。现改用统一启动器，失败不再显示排队成功提示。

- 排行榜提供可选 Gym 官方比赛、题目或提交链接，严格限定 HTTPS 官方来源、路径与字段；链接仅作为查询范围，不作为 AC 证据。普通无正文及空正文采集请求继续兼容。
- 比赛范围按隔离用户库及 CF 账号保存；在网络请求前以事务合并，不覆盖其他并发任务新增的范围。后续账号采集和题库同步会补查已知范围。
- 先读官方比赛 API，不可读时尝试同一官方比赛状态页。仅保存账号、题号、提交号、官方判题和可靠时间匹配的记录；正文不接受客户端上传的源码、HTML 或 AC 断言。
- 榜单所选日期会传入采集，可补同步最近一年某日起的记录。AC 按北京时间真实提交日期归日、按平台及题号去重；重复 AC、跨天补同步、WA、判题中和其他账号不会制造今日完成量。
- Gym 官网链接不会再误指普通 problemset；工作台识别 Gym 题号和官方题面链接，可补查提交。Gym 远程代交仍明确禁用，防止发往普通题库表单。
- 无权限、Cookie 不可用、安全验证、无法确认时区、格式变化、分页重复及查询预算耗尽均保持不完整并保存历史；部分同步结果在榜单上可见。不会根据一个链接假造通过或将访问失败当成零记录成功。
- Gym 补查不覆盖完整账号采集水位、评级资料或快照；不提交代码、不运行代码，也不把 AI/自测结果计入榜单。

## 尚待真实环境确认的边界

官方用户历史无法发现的全新 Gym/Mashup，需要首次提供比赛范围；不能宣称自动发现所有私有比赛。每账号最多 20 场，单场 API 最多 1000 条或官方网页 5 页，并受单场/整轮时间预算约束。

服务器必须实际能读取对应账号有权访问的官方记录，且时间有明确时区或 Unix 属性。没有访问权限、Cloudflare 仍拦截或页面缺少可核验时间时，本轮只能明确报告不完整，不能保证拿到私有 Gym 的准确总数。用户反馈的真实记录仍未通过真实访问复核，不冒充已成功入库。

操作方式及接口参数见 [社交指南](SOCIAL.md)。官方时间字段定义参考 [CF Submission 对象](https://codeforces.com/apiHelp/objects#Submission)，具体接口参数参考 [CF API 方法](https://codeforces.com/apiHelp/methods#user.status)；这些文档不构成私有比赛始终可访问的保证。
