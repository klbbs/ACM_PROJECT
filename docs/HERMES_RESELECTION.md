# Hermes 程序初筛与评分重选

本协议补充结果[回执协议](HERMES_DELIVERY_PROTOCOL.md)，不改变固定请求键、消息摘要、ACK及5秒重发规则。生成前可以重选；生成完成后只能交付已保存结果，绝不因未收到回执重选或调用AI。

## 实际执行流程

1. 同步本人已验证平台的历史；仅使用本轮历史完整的平台，排除已提交、已完成/跳过、对战占用、已由Hermes交付及网页推荐/每日/专项已出题、客户端exclude_ids和其他任务占用题。标签表达式与日期规则沿用现有实现。
2. 程序执行难度及统计初筛，构成最多600题的候选池；预览仍只返回60题，不代表全库数量。未知统计不冒充0%，存在已知难度时允许注明限制后沿用；没有任何可用难度证据则不入池。
3. OS系统随机源先按平台权重抽平台，再在平台内抽题；保留原strategy名称。候选在任何await前从本轮移除，以SQLite写事务取得题号租约，两个进程不能同时付费分析同一候选。Gym优先分只影响概率，不能抬高难度。
4. 读取完整题面和样例。CF普通题允许固定洛谷公开镜像，严格匹配`CF{contest}{index}`，保留mirror_url和source，不映射Gym、不将CF凭据发送到镜像。镜像的AI报告明确说明差异风险。单题获取失败先换题，同平台连续两题不可读才跳过该平台。
5. AI根据最简单可行解法独立评分，不提供统计预估供其照抄。低于请求下限、超过预筛上界、不适配或无法判断，保存评分并从剩余池继续随机抽取。完整报告再次评分，不达标同样继续，不降目标交付。程序随机出的精确题号由schema锁定，AI不能编造另一题。
6. 最多12次新评分、4份新报告，包含同步在内最多1200秒；官方Codex完整报告单次等待420秒，其他任务默认仍240秒。API提供方保留用户自己的超时设置。实际达到候选耗尽、取消、预算上限或AI提供方故障时明确停止，不无限重试、不静默切模型或思考强度。

## 可解释的统计基础规则

规则版本`success-sample-ceilings-2026-11-18.1`持久附在`problem.score_evidence.base_filter`中；是应用初筛启发式，不冒称官方等价或AI已阅读题面。CF已有比赛综合估计仍为55%实测、45%官方评分，不重复做加权换算。统一额外样本缺失不等于CF比赛估计也缺失：已有contest_statistics仍通过综合估计参与初筛，结果保留各自来源和分母。

- 仅接受精确官方来源、有效观察时间、计数、分子分母和计算一致的通过率。人数与次数不混用、赛时与全站累计不混用。
- 比赛人数通过率需至少100个尝试者：通过率≥98%、95%、90%时，初筛难度上界分别1200、1400、1600。
- 洛谷全站提交通过率需至少1000次提交：通过率≥95%、90%时，初筛上界分别1600、1800。累计提交样本有不同偏差，不能套用人数规则。
- 上述只剔除样本明显过易且请求预筛下界高于上界的候选；不把一个比率当作精确定级。题库无原生难度但有有效统计时可用`1200 + 400*log2((1-r)/r)`作低置信度粗筛，r为同来源加一平滑率，裁剪800～3500；最终仍须AI读题确认。
- 这些阈值未经共同选手标定，尝试者群体、比赛环境与重复提交会有偏差；完整题面AI评估才是最终门槛，且AI本身也可能误判。不能宣称数学保证每题真实达到目标。

## 持久排重与成本语义

评分存在本人数据库`hermes_candidate_reviews`，按精确题号、完整题面指纹和上下文摘要绑定；摘要包含AI配置指纹、提供方/模型、分数区间、规范题型、提示词和基础规则版本。拒绝评分不会记为已交付、完成或签到。

同上下文下，已知低分/高分/不适配题会从新任务池排除，避免再次付费；未知置信度仅缓存一天。题面变化、模型/AI配置/分数/题型/规则变化允许重新评估，不形成无条件永久封题。已存的适配评分可复用；外部共享报告不能代替当前上下文的读题评分。旧版失败任务没有保存候选评分，无法凭空补造历史拒绝记录。

候选占用存在`hermes_candidate_claims`。完成写入交付/排重与释放占用处于同一个事务；失败或取消释放，崩溃后的终止任务/过期租约可回收。最终交付仍重新核对登录、历史/占用、题面指纹并用原有交付唯一约束兜底。

## 客户端兼容

原POST/GET、三种selection_strategy、exclude_ids上限10000和ACK端点不变。capabilities新增execution_budget与review_memory_policy。

GET任务附加`selection_progress`：candidate_count、selected_count、ai_review_calls、report_attempts、max_difficulty_reviews、max_report_attempts、max_run_seconds、elapsed_seconds、current_problem_id、reviews、failure_reason。reviews只包含题号、评分、置信度、决定和是否复用，完整报告另行读取。新增阶段reviewing_difficulty、rerolling。进度不是百分比，也不能据此当成成功。

失败仍保留error字符串及原状态，同时给出固定error_code：

| code | 含义 |
| --- | --- |
| hermes_candidates_exhausted | 筛选或重选后候选耗尽 |
| hermes_review_budget_exhausted | 达到本次新评分次数预算 |
| hermes_report_budget_exhausted | 达到本次完整报告次数预算 |
| hermes_deadline_exceeded | 整体时限已到，已尽力中断 |
| hermes_cancelled | 用户取消 |
| hermes_generation_failed | 其他无法进一步分类的生成失败 |

AI提供方故障沿用ai_auth_required、ai_timeout、ai_rate_limited等安全白名单。原始上游错误正文不外显。旧任务没有新进度时返回空对象，不伪造历史。客户端恢复只能查原键；有界等待耗尽显示pending，不能偷偷新建付费任务。
