# Hermes 跨平台回退与权重开发记录

## 原始位置与原因

- 线上本人最近20条任务中，成功结果有12次AtCoder、1次CF；存在CF历史分页不完整直接终止的原始错误。
- `history.synchronize` 曾在首个平台同步不完整时直接抛错，导致健康平台没有继续机会；CF题库刷新失败也会终止整个任务。
- `Hermes.run` 曾把CF候选限制在有限统计采样的比赛内；最终按每道题加权，使较大平台候选池获得额外概率。

## 修改

- 同步历史按平台隔离故障，保存已读记录但不推进失败账号进度；只从本轮历史完整的平台抽题。所有平台不可用才停止，不把未知历史当成未做过。
- CF题库失败跳过CF；官方题面读取失败先换其他平台，尚未取得题面时不调用AI。报告明确不适合时最多尝试两个平台，保持600秒总预算；共享AI提供方故障不通过换平台盲目重复收费。
- 先抽平台再抽题，各可用平台基础权重相同；最近8次成功结果中出现次数越多权重越低，上次平台再减半。平台内部保留原统计适配及Gym优先权重。
- 有充分统计的题继续按综合分筛选；有限统计采样不再排斥所有其他有官方rating的普通CF题。未知难度Gym仍排除。
- 结果提供候选数量、平台权重、跳过原因及报告次数；日志只记平台与固定错误分类，不记录凭据、模型正文或原始异常。结果完成后的回执重发仍读取同一持久结果，不重新生成。
