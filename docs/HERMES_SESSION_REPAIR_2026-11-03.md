# Hermes 抽题登录证据故障定向修复

## 原问题定位

经用户授权，只针对当前线上抽题故障检查。对照本地 Hermes 请求与服务器对应任务，确认线上版本为0.21.9，本次1800分图片抽题约49秒后在付费AI调用前失败，原错误为“没有已验证登录的平台”。紧接的下一次请求成功，因此不能将本次归为此前的报告524故障，或直接认定所有保存的Cookie永久失效。

旧日志只保存了任务最终错误，未保存当时逐阶段的认证缓存状态，无法事后精确区分该次的临时负缓存与中途有效期耗尽。对应实现中已定位并复现两条能产生同一原错误的路径：

- `refresh_recommendation_sessions` 把检测器五分钟内的所有状态都当作无需刷新，包括未知、超时和访问受限；检测器自身实际仅复用60秒，导致本来可以恢复的检测被跳过。
- 抽题在题库同步与比赛统计读取后直接建候选池；之前成功的身份检测若在这些长步骤间过期，就会在建池时报无已验证平台。其中统计入口本身也先建发现池，只在统计结束后续验不够。

检测器还在请求开始时记录`checked_at`，请求时间提前消耗了有效期。源码与服务器目标模块的修补前指纹一致，定位的是实际运行版本，不是其他分支。

## 修改

- 成功认证按真实五分钟窗口与所需剩余有效期决定是否续验；负结果按60秒复用和上游Retry-After冷却恢复，不强制刷新、不循环重试、不继承失败前认证。
- 真正检测/解析结束时记时间；复用缓存仍保留原时间。账号摘要与当前凭据不一致时不缓存或认领身份，检查开始的防抖仍保留。
- 原抽题流程在历史同步前后、统计入口前、统计后选题前、最终交付前按需续验，关键边界要求60秒剩余有效期。每次续验后仍核对账号版本、模型配置以及已同步身份集合，新增平台不能绕过历史同步。
- 增加固定阶段与有界计数日志；无有效身份时记录固定失败原因，不存用户名、Cookie、题目、平台返回正文或原始异常。预览GET不触发平台检测。

## 定向自检与线上操作

- 受影响检测、连接、推荐、Hermes流程及日志范围225项通过，随后新增的两个身份集合/取消边界回归也通过（同文件57项通过，总计227个不同用例）。合成平台/模型响应不代表真实OJ或付费模型成功。
- 包含真实检测器与可控时钟的图片抽题回归：题库或统计推进时间跨过认证有效期后，原流程会重新检测并继续；始终无法验证时在AI前停止，缓存读取不续期，限流/错误身份不能变成认证。
- Python编译、差异检查与代理只读复查通过；没有运行全项目检查。
- 仅修补四个相关运行模块，备份原镜像与源码；没有升级依赖或应用版本，没有改账号、模型、数据库或其他服务。首次重建因未指定既有Compose项目名而创建了未启动的临时服务并遇到端口占用，原服务未受影响；确认后只清理本次临时容器和空网络，再按原项目名重建web。保留只读文件系统，替换前确认无运行任务或正在发送的提交。

真实复测已完成：使用现有本人会话调用原 `/api/hermes/draw/image`，请求相同1800分区间，不变更默认模型及预算。任务完成，完整题目说明与报告存在，一张图片成功下载且通过PNG格式检查。阶段日志确认历史前后、统计前后和交付前均检查认证；已验证身份保留，未验证状态仍遵守冷却。这里没有故意让线上认证过期，跨期场景由可控时钟测试覆盖，不将该合成场景描述成真实上游故障复现。

旧失败任务保持失败状态，未重写历史结果、绕过幂等保护或修改本地Hermes练习数据库；只额外发起这一次明确的真实复测，没有自动重复付费。仓库不保存实际用户、提交/题号、任务标识、私密请求或模型正文。

本次不标注新版本、创建标签或修改发布公告。服务器保留0.21.9，只应用上述故障范围内的修补。
