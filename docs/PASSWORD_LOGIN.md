# 平台账号密码登录（0.17.0）

入口在「连接与设置 → 平台信息、登录检测与交题」，展开 Codeforces 或 AtCoder 的「账号密码登录」。牛客使用已有的微信扫码；洛谷继续公开资料同步和官方网页交题。

## 使用方式

1. 填写平台用户名；CF也可使用登录邮箱。密码仅用于本次请求，提交后输入框立即清空，ACM Lab不保存密码。
2. 可选填写绑定目标用户名。官方当前登录身份与目标不一致时，不修改原绑定。
3. 点击「尝试登录并绑定」。服务器在同一临时会话请求固定官方登录表单、提交表单，再读取官方设置页核对当前身份；只有可靠确认当前身份后，才保存该会话的Cookie。
4. 浏览器验证、验证码、平台拒绝或无法确认身份时，页面明确提示未绑定，不覆盖其他账号。请在官方页面登录后使用Cookie绑定；其他浏览器完成验证不会完成本次服务器会话。

此流程不提供自动代交。代码仍需在官方提交页提交，浏览器本身也需登录平台。

## 实际可用边界

这是服务器请求登录的尝试入口，不保证平台允许无桌面请求登录。验证码、Cloudflare和出口限制可能阻止流程；完整Cookie也不能保证另一服务器出口获准访问。

本轮本机网页真实尝试：CF返回浏览器验证；AtCoder首次未完成登录，随后只读核对发现官方密码表单包含需要JavaScript生成的Turnstile验证。新增登录前识别后，真实复测只发送了一次官方登录页GET（HTTP200），即返回浏览器验证阻断，没有向平台POST密码，两者均未绑定。不能将合成测试的成功分支当作真实账号密码登录已经跑通。之前CF与AtCoder通过的是官方网页登录后导出Cookie的身份验证，和本站密码入口是不同流程。

## 凭据和会话

- 请求必须经过本站当前用户会话与CSRF验证；每用户的账号、临时登录和检查结果相互隔离。
- 密码只在当前请求使用，不进入配置、日志、响应、AI或发布包；只保存可靠验证后的Cookie。
- 固定HTTPS地址、严格同源表单与已知跳转检查，不跟随平台提供的任意地址；限制响应大小、总时间与并发，失败使用本地固定消息。
- 登录期间修改账号配置、注销本站或撤销会话，旧结果不能写回覆盖账号。
- 每工作区设置尝试冷却，平台限流时延长等待；验证码不会自动求解或嵌入本站执行。
